## The 99.9% target

No model here reaches 99.9%, and the test sets are too small to demonstrate it even for a perfect model: with zero errors, the upper 95% bound on the error rate is roughly 3/n, so showing an error rate below 0.1% needs about 3,000 error-free test samples *per class*, from the production camera and lighting. The platform is built to get there honestly (review band, calibration, drift monitoring, active learning, per-version evaluation records) rather than to claim it.

## Model cards

### `concrete_crack_segnet` 1.0.0 (segmentation)

* **Architecture:** MobileNetV2 encoder (ImageNet transfer) + FPN decoder, 320x480, CE + Dice
* **Material:** construction
* **Data:** CrackForest (CFD)
* **Splits:** `{"train": 58, "val": 30, "test": 30}`
* **Training:** `{"epochs": 60, "train_images": 58, "train_seconds": 402.6, "optimizer": "AdamW+OneCycle", "lr": 0.001, "batch": 8, "augmentation": "flips, brightness/contrast jitter"}`
* **Limitations:**
  * CrackForest has 118 images (urban road surface, one phone camera); the test split is only 30 images.
  * Every image contains cracks, so image-level false-positive rate / AUROC cannot be measured; automatic PASS is disabled by default.
  * Ground-truth cracks are 1-3 px wide, so strict pixel metrics are sensitive to 1 px offsets (2 px tolerant metrics also reported).

### `material_id` 1.0.0 (material_identification)

* **Architecture:** nearest-centroid over mean MobileNetV2 patch features
* **Material:** -
* **Data:** MT + DeepPCB + CrackForest (<=400 images each)
* **Splits:** `null`
* **Limitations:**
  * Knows only the three materials/imaging setups it has prototypes for; these datasets are visually trivial to tell apart, so this accuracy says nothing about distinguishing e.g. steel from aluminium.
  * Anything farther from a prototype than 90% of that profile's own training images is reported as 'unknown' and the operator is asked to choose (so roughly 1 in 10 genuine images is also asked). Rejection of truly foreign materials was not benchmarked.
  * It is a suggestion only: the operator's selection always overrides it.

### `mt_patchcore` 1.0.0 (anomaly)

* **Architecture:** PatchCore: frozen ImageNet MobileNetV2 (blocks 6+13), 3x3 avg-pooled patch features, greedy k-center coreset (4000), 1-NN distance
* **Material:** ceramics
* **Data:** Magnetic Tile Surface Defects
* **Splits:** `{"test": {"good": 202, "blowhole": 23, "break": 18, "crack": 12, "fray": 5, "uneven": 17}, "val": {"good": 192, "blowhole": 22, "break": 22, "crack": 11, "fray": 7, "uneven": 21}, "train": {"good": 558, "blowhole": 70, "break": 45, "crack": 34, "fray": 20, "uneven": 65}}`
* **Trained on:** train split, defect-free images only
* **Limitations:**
  * Validated only on the Magnetic Tile dataset (grayscale ferrite tile surfaces, one imaging setup).
  * Test split has 75 defective and 202 good images: far too few to verify a 99.9% target (see the confidence intervals).
  * Images are resized to a fixed square input; very small defects (blowholes) lose resolution.

### `pcb_refdiff` 1.0.0 (reference)

* **Architecture:** template differencing + CropNet (4-block CNN, 2-channel 64x64 crops)
* **Material:** electronics
* **Data:** DeepPCB (official split; 20% of trainval held out for validation)
* **Splits:** `{"train": 804, "val": 196, "test": 500}`
* **Training:** `{"epochs": 14, "train_crops": 13706, "train_seconds": 625.2}`
* **Limitations:**
  * Requires an aligned defect-free template of the same board region (golden-reference inspection).
  * DeepPCB images are binarized line-scan crops at ~48 px/mm; photographs of populated boards are out of distribution.
  * DeepPCB contains no defect-free test images, so image-level false-positive rate and AUROC cannot be measured; only defect-level precision/recall are validated. Automatic PASS is therefore disabled for this profile by default.
  * Most DeepPCB defects were synthetically added by the dataset authors following real defect patterns.
  * The official trainval/test split shares board groups between splits (we keep it for comparability).
